## 项目总纲

研究者给出目标、资料和约束。Agent 从团队资料库检索证据与适用配方，经 AgentArts 调用成熟上游的研究工作流，保存原产物，并依据真实结果自主选择和执行下一步。Auto Research 保存项目、证据、行动和预算，队友能从原记录接续。OKS 是团队资料管理候选，先复用已实现的带出处检索接口，接入情况按实际回执报告。 [产品宪章](../../execution/pack-v2/00-charter/PRODUCT_CHARTER.md) · [已有配方接入](../../recipe-research/integration.md)

首批目标是十个或更多源自成熟项目的配方。每个绑定具体可执行入口、固定上游版本、原始输入与产物、评价口径、适用条件和一项可验证的 ICT 改造。优先直接调用原实现。上游已发表结果注明出处，可作为基线。本项目的评分复算、原版复现、平台调用和真实任务实测各自附回执。

上一轮 GovInfo M0、M1、M1b 的原件和结论保留。M1 与 M1b 各使用 2/2 研究行动，M1b 代理记录仍待本人确认。新的持续计划从上游工作流适配开始。 [旧阶段计划](execution-plan.md) · [M1b 复核](m1b-verification-20261119.md) · [键契约](key-contract-20261119.md)

## WorkBuddy Agent 团队与分工

接手后由 WorkBuddy 组建执行团队。优先复用能继续工作的已有成员，缺少对应成员时按宿主能力创建。默认一名 WorkBuddy 主控、三名成员 Agent。项目 Owner 是用户，负责方向、预算和需要本人决定的授权。

| 角色 | 首批任务 | 职责和交付 |
| --- | --- | --- |
| **WorkBuddy 主控** | W01，统筹 W05、W06 | 核现场、持有队列、协调查证与写入、集成产物。由主控更新共享契约、当前状态和三小时对齐摘要，处理真阻塞，把验收过的结果排进下一轮。 |
| **上游工作流 Agent** | W02、W04，并为 W05 准备数据来源及原评价 | 固定上游版本、许可、原入口、输入和参考结果。先做 M4 官方评分复算，再按优先级核 BEIR、OR-Tools 及其他候选。交上游清单、原命令、原输出、失败记录和配方卡建议。 |
| **产品接入 Agent** | W01 后并行核接入入口，W02 有原输出后接 W03 | 使用现有检索、控制器、AgentArts 桥接和产物记录。交最小适配、正常入口的调用回执、结果对应关系和原请求恢复证据。后续接通证据触发下一工作流的产品路径。 |
| **独立评审 Agent** | 并行准备 W02/W03 的复核，并审核 W05 和 W06 | 回源核对固定输入、原评分器、容差和结论边界。对实际产物独立复算或抽查，核原请求与预算。交逐项结论、差异、阻塞及修订复核。同一项的独审由未参与实现或标注的成员承担。 |

W01 完成后，主控同时发出三条任务。工作流 Agent 跑 M4 或排查其前提，接入 Agent 查明正常调用入口和最小接口，评审 Agent 根据上游示例独立确定复核办法。M4 产物返回即转接 W03，再交评审。工作流 Agent 同时领取下一个可做的候选，接入与评审也各自接续独立工作。后续同类任务优先交回已有上下文的成员。

每次派发给出任务号、具体入口、能力或文档、允许编辑的文件、交付物和验收方式。接入角色先按项目开发导航加载对应索引。涉及 AgentArts 的中国站操作才读项目的 AgentArts Skill。使用宿主实际可用的能力，记录成员和任务接收状态。每个文件同一时间由一人写，共享接口和状态由主控集成。三小时对齐时，各 Agent 汇报交付物、状态与下一动作，手上的任务照常推进。 [项目开发导航](../../../.agent/README.md) · [AgentArts 接入 Skill](../../../.agent/skills/agentarts-china-builder/SKILL.md)

若宿主可用席位较少，优先保留独立评审。主控可兼任上游工作流或产品接入。只有单代理时，主控继续完成可做项，自检后标记 `needs_review`，后续交给独立评审。

## 阶段交付

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| **P0 · 接手和冻结起跑线** | 实际仓库、分支与 HEAD，未提交改动、旧运行可见性、资源和权限。把下方队列写入当前接续记录 | 能指出首个可运行任务和原始入口。旧请求、旧预算及别人的改动有明确归属 |
| **P1 · 对齐上游原结果** | M4 Hourly 上游公开预测评分复算。BEIR 官方 SciFact 示例的入口与环境核查，条件可用时复跑原后端。保存版本、输入、原评分器、命令和实际输出 | M4 的三个指标与作者给出的断言一致，容差沿用原示例。同一个冻结输入单独运行与经 ICT 调用时，输出口径一致。BEIR 的原后端和本项目本地对照各自登记。BEIR 阻塞时可并行用 OR-Tools 官方小例验证通用调用入口 |
| **P2 · 建成首批配方库** | 十个或更多上游工作流的版本化配方，带原入口、数据与许可、典型输入、原产物、失败条件、反馈分支和 ICT 改造点 | 每条入库配方有可重跑的最小例和本项目调用记录。条件不足的候选标明阻塞及可替代来源。至少覆盖资料研究、数据评测和工程计算 |
| **P3 · 验自主推进** | 在已获批的独立真实任务里，AgentArts 同一项目完成至少两轮。保存第一轮结果、触发下一轮的证据、第二轮行动和结果。另一类课题验证同一底座能选不同配方 | Agent 在授权内主动发起下一步。独审能从画布或工作台点回原产物，并按原请求接续。用同输入、同工具、同总预算对照强固定流程，记录改变的决定、结果、人工干预和成本 |
| **P4 · 赛题二交付** | 完整 AgentArts 运行记录和视频、真实案例与复现说明、结果和限制、团队接续记录与作品材料 | 队友能照说明从干净环境复核代表样板。证据逐项对应演示主张，失败实例、平台边界和未验项可查 |

各阶段可交错推进，发布和实验升级以实际验收及授权为准。记录失败后可修正、替换候选或保留为负结果。

| Matbench | `matbench_steels` 固定折与 AMMExpress 发布结果，先核可重算的原产物，再评估旧版环境可行性。 [原结果](https://github.com/materialsproject/matbench/blob/main/docs_src/Full%20Benchmark%20Data/matbench_v0.1_automatminer_expressv2020.md#matbench_steels) |

| OR-Tools | Job Shop 官方例，固定约束和目标，保留排程及求解状态。 [上游代码与输出](https://developers.google.com/optimization/scheduling/job_shop) |
| NumPy ASV | 官方版本对照流程，固定环境核对重复计时和退化项。 [上游基准](https://numpy.org/devdocs/benchmarking.html) |
| Fairlearn | Credit Loan Decisions 的离线研究示例，保留原分组指标与干预前后对照。 [上游 notebook](https://fairlearn.org/main/auto_examples/plot_credit_loan_decisions.html) |

## 持续运行、对齐与恢复

- **一次任务验收就立即领取下一项。** 主控按依赖和优先级循环推进。单项等待时把具体阻塞留在队列，转到仍可做的独立任务。每完成一个增量保存交付物和接续点，当轮继续。
- **每三小时用北京时间对齐。** 从实际启动点计时。核对本计划和总纲、阶段目标、真实产物、预算、阻塞与接下来的优先任务。记录对齐后继续正在做的工作。长步骤仍在运行时，保存其身份、状态和下次核验点，避免启动同一工作两次。
- **会话断开就恢复。** 每个小任务结束和宿主即将回收时，持久记录任务 ID、执行人、状态、真实产物路径、源码身份、原 project/run/request ID、用量、下一个可执行动作和时间。重启先查在途状态及 lease。对 `pending` 或 `unknown` 从原请求对账，确认可恢复后用原 ID 和原输入继续。复用项目已有协调办法。当前环境若不能运行 lease，则保持单写者，无法确认同一工作树归属时在独立位置推进。
- **宿主接续能力另行核实。** 若 WorkBuddy 已有续作机制，按实际运行回执确认上一轮的停止与下一轮的恢复。三小时是对齐间隔。平台结束会话或离线时保存可接续状态，实际间隔和执行状态如实汇报。 [既有接续约定](../../execution/AUTONOMY.md)

使用现有共享累计 **5 CNY** 现金边界，现有结算不明时写 `unknown`。准备和已有授权内的零新增现金核验可以继续。新真实研究、额外模型调用、付费、平台状态变更和外发均按相应授权处理。旧预算与冻结输入不因换目录、三小时对齐或换执行者重开。报告区分上游成绩、本项目复算、原版复现和真实自主运行。

启动时使用 [WorkBuddy 启动指令](continuous-handoff.md)。
