## 4. 分母为什么会自己变：144 → 145

跑扫描时得到 **145 个入口**，而第 11 轮写的是 144，中间没有任何人改过被扫描的代码。归因是可核的：

```
git ls-tree --name-only 5c406f6 scripts/ | grep -c '\.py$'   -> 144
git ls-tree --name-only 2e3a665 scripts/ | grep -c '\.py$'   -> 145
diff                                                            -> > scripts/recipe_transcript_check.py
```

**第 12 轮新增的那个校验器自己进了分母。** 于是「20 dead / 144」与「20 dead / 145」看起来是两个可比的数，实际不是。这与第 11 轮记下的「提到某词的文件数会改变该词的计数」是同一族错误的第三面：前两面是「`grep | head` 截断少计」和「新写的扫描器自己贡献 11 行 `fcntl`」，这一面是**分母变了而分子没变**。

修法是给分母一个身份，而不是给个数：

```
Population: sha256:e9fe6f05c1e4475dd7747b8a03a715203773f1e9721c70ec61545beefb6c9e19
```

`population_sha()` 只哈希**入口名集合**（排序后拼接）。它因增删/改名而变，不因某个脚本内容改动而变（内容变化由逐条 verdict 承担）。加在 `--json` 的 `population_sha256` / `population_size` 与文本输出的 `Population:` 一行；自检 **11/11 → 13/13**（T11 顺序无关、T11b 新增脚本必变），退出码 0，两次扫描输出逐字节相同。

此后任何一轮引用「N 个入口里 M 个判死」，必须同时报 `population_sha256`，否则两个数不可比。
